## やること

### 1. 「本当は期間ではないか」を全イベントで疑う
点で書かれている状態・在籍・継続を期間に変える。典型例:
- 在任・在籍・稼働・連載・在位・保有・居住・勤務の**期間**
- 好況/不況・戦争・流行・ブーム・規制の適用期間・訴訟の係争期間
- 「◯◯が首位だった時代」「◯◯方式が標準だった時期」のような**支配的だった期間**
- 「Aの開始」を点で書いているとき、その終わりが分かるなら期間にする

### 2. 足りなければ期間イベントを新設する
その年表の背景として走り続けていた**時代の線**（例: 高度経済成長、冷戦、バブル、コロナ禍、特定技術の世代）を、既存レイヤーのいずれかに追加する。ただし史実として期間が言えるものだけ。

### 3. 重なりを設計し、本文で言及する
**異なるレイヤーの期間が重なる場所**に、その年表の発見を置く。見本の例:
- 「バブル景気の線が途切れる、まさにその月に家を買った」
- 「持ち家30年の線の上に、単身赴任3年の線が並走する」
本文（summary 第2段落）で、重なっている相手の線に触れる。

### 4. 目標値
- **1年表に期間4〜12件**（点イベントも残す。全部を期間にしない）
- イベント総数は **14〜22件**（既存が20件なら、点を期間に変えるのが主。新設は2〜4件まで）
- 同一レイヤーの連続する状態は、端点を接続して**途切れない1本の線**にする
- 進行中の期間は end_date を `2026-06-30` 前後でキャップし、本文で「現在も続く」ことを示す

## 厳守（変えてはいけないもの）
- `slug` / `title`（**絵文字を含めて一字も変えない**）/ `category` / `language`
- `layers` の name と color（レイヤー構成は不変）
- **既存のペルソナ文体**（です・ます／である／一人称、絵文字の量、口調）。読んでから同じ声で書く
- 史実の正確さ。期間の start/end は根拠のある日付だけ。**曖昧なら precision を粗くするか credibility=disputed + note**
- 出典（sources）は対応するイベントに残す。新設イベントにも可能なら付ける（**URLは捏造しない。不確かなら url:null）**

## フォーマット規約
- `summary` は **2段落**（`\n\n` 区切り）・110〜300字・`detail` は常に null
- 強調 `**…**` は **1年表4〜8箇所・1イベント1箇所まで**（イベントを変えたら位置も調整してよい）
- 「!」は AUTHORS.json の tone に「使用可」とあるペルソナのみ
- 期間イベントは `type:"period"` + `end_date`（必ず date 以降）。`title` は期間だと分かる書き方にする（例: 「〜の19年」「〜、はじまりの9年」「〜の51か月」）
- イベントは**年代順**に並べる。`start_year` / `end_year` は最古・最新に合わせて更新する
- 各レイヤーに最低3件
