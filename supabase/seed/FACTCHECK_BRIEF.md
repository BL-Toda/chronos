# シードコンテンツ ファクトチェック ブリーフ（2026-08-25）

公開前の事実確認。Chronosは「分からないことは分からないと表示する」ことを売りにしているため、**自分のサンプルが不正確だと商品価値そのものを毀損する**。

## 検証の優先順位

1. **`credibility: "verified"` で日単位(`precision:"day"`)の日付** — 「確実」と表示しているので誤りが最も痛い
2. **具体的な数値**（金額・人数・件数・順位・シェア・記録）— 報道ベースの概算が verified になっていないか
3. **「世界初」「史上最大」「初めて」などの最上級表現** — 反例があることが多い
4. **期間イベントの端点** — 今回の期間強化で新設・変換したものは特に
5. **固有名詞の表記**（人名・組織名・作品名・法令名）

## 判定と対応

| 判定 | 対応 |
|---|---|
| 明確な誤り（日付・数値・固有名詞） | **直す**。本文の該当箇所も整合させる |
| 確実とは言えない（諸説あり／出典が報道のみ） | `credibility` を `disputed` か `unverified` に下げ、`credibility_note` に**何が不確かなのかを一文**で書く |
| 精度が怪しい日付 | `precision` を `day`→`month`→`year` と粗くする。日付自体は月初/年初に丸める |
| 判断がつかない | **触らずに報告する**。憶測で直さない |

## 厳守

- **URLを創作しない**。実在に確信が持てないURLは `"url": null` にしてタイトルだけ残す
- 本文（`summary`）の**文体・ペルソナの声・段落構成・強調 `**…**` の数と位置**を壊さない。事実に関わる語句だけ最小限で直す
- `slug` / `title`（絵文字含む）/ `category` / `layers` / イベント数は変更しない
- 期間の `end_date >= date` を保つ。`start_year` / `end_year` を変えたら整合させる
- 「!」は AUTHORS.json の tone に「使用可」とあるペルソナのみ
- `build-seed.mjs` / `build-review.mjs` の実行と git 操作は**禁止**（親側で一括実行）

## 最終報告（これが成果物）

ファイルごとに:
- **修正した誤り**: 何がどう間違っていて、何に直したか（根拠も）
- **信憑性を下げたもの**: どのイベントを何から何へ、理由
- **判断がつかず残したもの**: 何が引っかかったか（親側で人手確認する）
- 誤りが見つからなかった場合もその旨を明記する

推測で「たぶん正しい」と流さないこと。**引っかかった違和感は必ず報告に残す**。
