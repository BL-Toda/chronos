## D2. イベントスキーマ v2

**D2-1. 期間イベントの正式化**（現状: UI4画面の中核なのにDB/API/AI出力に無い）
- ★ A案: `events` に `end_date DATE NULL` と `event_type TEXT CHECK('point','period')` を追加。API（POST/PATCH events、events/bulk）とAI生成出力スキーマも同時改訂
- B案: 期間イベントを廃止しUIから外す（非推奨: viewer/creation-flow/period系の中核機能を失う）
- 決定: ☐

**D2-2. イベント本文の構造**（現状: プロトタイプは summary+detail の2階層、DBは description 1フィールド）
- ★ A案: `summary TEXT NOT NULL`（一覧・カード用の短文）+ `detail TEXT NULL`（展開時の本文）の2カラム化
- B案: description 1本のまま「冒頭N文字を要約扱い」と仕様に明記
- 決定: ☐

**D2-3. 信憑性・出典・レイヤー割当の編集UI**（現状: USPなのに編集パネルに入力欄が無い）
- ★ A案: 編集パネルに (1) 信憑性3択（確認済み/諸説あり/未検証）+補足メモ (2) 出典リスト（URL+タイトル、複数） (3) レイヤー選択 を追加する——スキーマは既存定義（credibility, event_sources）を使用
- 決定: ☐

**D2-4. timelines側の追加カラム**
- ★ A案: 以下を一括追加
  - `language TEXT`（explore言語フィルタの前提）
  - `start_year INT` / `end_year INT`（年代フィルタ用キャッシュ、イベント登録時に更新）
  - `bookmark_count INT DEFAULT 0`（D3-3の前提）
  - カバー表現: `cover_seed TEXT`（Explore v3の「カテゴリカラーベース生成型カバー」をシードから決定論的に生成。画像アップロードはMVPでは持たない）
- 決定: ☐（個別に外すものがあれば指定）

**D2-5. レイヤー名の最大長**（確定版仕様30字 vs API/DB 60字）
- ★ A案: 30字に統一（API設計書を改訂、入力欄にmaxlength付与）
- 決定: ☐

## D3. 公開系UX

**D3-1. 公開設定UI**（現状: DB/RLS/規約/APIまで定義済みでUIが全欠番）
- ★ A案: 作成フロー最終ステップ+年表設定モーダルの2箇所に「公開 / 限定公開（URLを知っている人のみ）/ 非公開」の3択+共有URL発行を実装。デフォルトは非公開
- 付帯: 「下書き」という独立ステータスは作らず「非公開」で代替（マイページのバッジ表記を「公開中/限定公開/非公開」の3種に統一）
- 決定: ☐

**D3-2. いいね**
- ★ A案: viewer（閲覧画面）にいいねボタンを新設し、exploreカードの♡もトグル化。DB/APIは既存定義（likes, like_count）を使用
- 決定: ☐

**D3-3. ブックマーク**（現状: CLAUDE.mdの想定通りDB未定義）
- ★ A案: `bookmarks`（likesと同構造: user_id+timeline_id複合PK）+ `POST/DELETE /api/timelines/:id/bookmark` をAPI設計に追記。UIはExplore v3タスク（カード🔖+マイページのブックマークタブ）で実装
- 決定: ☐

**D3-4. 公開プロフィール（chronos.app/@username）**
- ★ A案: MVP必須とする（共有動線の受け皿）。ただし実装はNext.js移行後で、先行してデザイン1枚（公開年表一覧のみのシンプル構成）を作る。「マイページ（私的ダッシュボード）」と「公開プロフィール」を用語・URLごと分離定義する
- B案: MVPから外す（プロフィールURLは404のままローンチ）
- 決定: ☐

**D3-5. 年表の削除と確認モーダル**
- ★ A案: マイページの年表カードに削除導線+確認モーダル（Danger色）を追加。アカウント削除にも確認モーダルを付ける
- 決定: ☐

**D3-6. 通報・モデレーションMVP**（現状: 規約は禁止事項を定義するがUI・運営フローが皆無）
- ★ A案: 最小構成で入れる——公開年表に「通報」ボタン → 運営へメール通知 → 手動で非公開化。admin画面はMVPでは作らない
- B案: ローンチ後に対応（公開プラットフォームとしてはリスク）
- 決定: ☐

## D4. プラン・価格・マスタデータ

**D4-1. プラン数値の正本**（現状3通りに分裂）
- ★ A案: spec-update-layers を正本とする——Free: AI生成 月3回 / AI Edit Assist 月10回、Pro: ¥800/月で両方無制限。chronos-screens.html の「月10回」「¥980」を修正し、Edit AssistはFreeでも使えることをマイページの使用量バーで可視化
- 決定: ☐

**D4-2. 年額価格の表記**（¥6,800は「2ヶ月分お得」と計算不一致）
- ★ A案: 価格据え置き¥6,800、コピーを「月あたり¥567」方式に変更（お得月数の主張をやめる）
- B案: ¥8,000に変更し「2ヶ月分お得」を維持
- C案: ¥6,800のまま「約4ヶ月分お得」と正確に書く
- 決定: ☐

**D4-3. カテゴリマスタ**（APIシード5種 vs explore 6種）
- ★ A案: explore準拠の6種で確定——テクノロジー / 歴史・政治 / カルチャー / 科学・自然 / ビジネス / 個人・ライフ（各slug+カテゴリカラーを同時に固定）。APIシードを更新
- 決定: ☐

**D4-4. レイヤーカラー**（CLAUDE.md 5色 vs 実装・sitemap 7色）
- ★ A案: 7色を正式トークン化——Blue #5B9BD5 / Green #7BC67E / Pink #D4849A / Gold #C8B87E / Purple #9E7EC8 / Teal #5BBCB4 / Orange #D4A05A。CLAUDE.mdとdesign-systemを更新
- 注: アクセントカラー全体の見直し（新ロゴとの整合）は別途。その際もレイヤー7色は独立して維持可能
- 決定: ☐

**D4-5. AI機能の呼称**（たたき台/土台/下書きの3種混在）
- ★ A案: 「下書き」に統一（ガイドライン・SNSコピーと一致）
- 決定: ☐

## D5. その他の齟齬（軽微だが決めておくと実装が迷わない）

**D5-1. 認証方式**（プロトタイプ: マジックリンク主導線 / 規約・DB・API: OAuthのみ）
- ★ A案: MVPは Google/Apple OAuth のみ（Supabase標準機能で完結、メール送信基盤が不要になる）。マジックリンクは将来検討。auth画面からメールフォームを外し、API定義済みの「初回username設定」画面を追加
- B案: マジックリンクを正式採用（メール基盤の構築とDB/規約改訂が必要）
- 決定: ☐

**D5-2. 通知設定の項目削減**（現状: 未仕様の「コメント」「週間レポート」等を参照）
- ★ A案: MVPは「いいね通知」「システムからのお知らせ」の2項目に削減（notifications.typeの現定義と一致）。通知インボックス画面はMVPでは作らずメールのみ
- 決定: ☐

**D5-3. 実名・問い合わせ**（screensにあるがDB/API未対応）
- ★ A案: 実名カラムは持たない（表示名+usernameで十分）。問い合わせはフォームをやめて `support@` メールリンクに簡素化
- 決定: ☐

**D5-4. share-embedの「Business」プラン表記**
- ★ A案: 削除（料金表はFree/Proの2段のみ）
- 決定: ☐
